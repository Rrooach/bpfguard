# Allox effects-supervisor peer

The Observer can run as one privileged, per-run sidecar owned by the Allox
daemon:

```sh
/absolute/path/bpf-state-observer supervise-effects \
  --recorder-object /absolute/path/system_effects.bpf.o \
  --drain-timeout-ms 5000
```

Configure that complete argv as Allox's trusted effects-supervisor command.
All run identity, the policy profile, exact cgroup path/ID, evidence directory,
and expected recorder SHA-256 arrive in `START` over a trusted private stdin
channel. Protocol v1 does not attach a request MAC to `START`; its one-shot
capability is generated by the caller and then authenticates the `READY` and
`FINALIZED` responses. `FINISH` is exact-bound on the same private input
stream, but is not independently MAC-authenticated. Therefore these fields
cannot be treated as workload-controlled only when Allox really owns and
isolates that input channel.

The sidecar follows this fail-closed order:

1. Read and validate one bounded `START` line.
2. Anchor the already-existing daemon-owned mode-0700 empty evidence directory.
3. Open the already-existing canonical cgroup-v2 leaf, match its inode ID, and
   verify both `cgroup.max.depth=0` and `cgroup.max.descendants=0`.
4. Verify and load the recorder object, install the START-selected profile, and
   register the exact cgroup/run epoch.
5. Emit response-authenticated `READY`. While waiting for `FINISH`, continuously
   drain the BPF ring instead of blocking on stdin.
6. Independently require the same cgroup inode to be empty and frozen, drain
   the recorder to durable `COMPLETE` transport, and unregister the run.
7. Commit a closed artifact set and `manifest.json`, then independently replay
   every WAL record against JSONL and health accounting.
8. Emit response-authenticated `FINALIZED` with `VERIFIED` only after that replay.

The closed Observer-owned directory contains exactly:

- `manifest.json`
- `system-effects.policy.json`
- `system-effects.health.json`
- `system-effects.raw.bin`
- `system-effects.jsonl`

All artifacts are created with create-new semantics and mode 0600. Allox writes
its protocol receipt outside this directory.

Supervisor protocol v1 deliberately selects `USER_INPUT` object resolution.
It does not silently opt into the partial BPF-LSM file-open mode. The manifest
states that attribution is direct exact-cgroup attribution, delegated causality
is not established, and operation history is not a final system-state diff.

On any directory, cgroup, digest, transport, protocol, artifact, or replay
failure the process exits without a `FINALIZED` message. Allox is responsible
for killing/fencing the run and for retaining or cleaning partial evidence.
